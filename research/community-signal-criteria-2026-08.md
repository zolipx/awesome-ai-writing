# 社区小众写作 Skills：收录与证据标准

> **整理：** Manus 1.6
> **适用范围：** “去 AI 写作味”、反套话、文本自然化、文风修订、编辑审校类 Agent Skills。

## 原则

本轮不将 GitHub Star 数当作主要判断依据。一个候选至少需要具备**可阅读的规则文件或明确可执行的工作流**，并同时具备下表中至少两类独立社区信号；单纯的 README 宣传、搜索摘要或匿名推荐不能单独构成收录依据。

| 证据类别 | 可接受的可核验信号 | 权重说明 |
| --- | --- | --- |
| 实际分发或安装 | skills.sh 等公开目录展示可复用安装入口、安装量或被多个 Agent 容器支持。 | 最强；优先于 Star。 |
| 实践性讨论 | GitHub issue/PR、Hacker News、Reddit、公开 X 帖文或技术社区帖子中，有具体使用体验、比较、问题或改进建议。 | 需要原帖可访问且不是作者自我宣传。 |
| 二次复用 | 第三方项目、Skills 集合、教程、工作流仓库或配置文件明确引用、安装或改编该 Skill。 | 强；可体现跨项目传播。 |
| 维护质量 | 近期提交、清晰许可、可读取的 `SKILL.md`、可解释的边界与测试。 | 必须满足的基础条件，不单独代表“效果好”。 |
| 中文适配 | 有中文规则、中文示例、中文使用者讨论，或经本仓库中文风格测试的明确表现。 | 对中文写作场景加权；英文通用规则不因此被排除。 |

## 排除规则

下列情况不收录为“社区推荐”：只有检测规避承诺；没有可核验规则内容；只有单一营销页面；伪造安装量或无法回溯来源；明显要求用户绕过学术、平台或其他规则。报告应区分“该项目存在”与“社区实际认可其效果”，并对证据强弱如实标注。
